# 커밋 & 푸시

커밋과 푸시는 되돌리는 비용이 다르다. 커밋은 로컬이라 거의 공짜로 되돌릴 수 있지만,
푸시는 원격에 올라가면 되돌리는 데 force push가 필요하다 — 이건 이미 승인 대상이다
(`/approval-check` 스킬). 그래서 이 스킬은 **커밋은 바로, 푸시는 사람 확인을 조건으로** 한다.

pytest/mypy/ruff 자동 검증 훅은 두지 않는다 — 필요하면 사람이 직접 요청해서 돌린다.

## 1. staged 파일 검토

`git add` 하기 전에 `git status`와 `git diff`를 확인한다.

- **의도한 변경만 포함되는지 확인한다.** 사이드 이펙트로 건드려진 파일이 있으면 사람에게 먼저 알린다
- **아래 경로는 어떤 경우에도 커밋 대상에 포함하지 않는다**: `.env`, `.env.prod`, `secrets/`
  (`.claude/CLAUDE.md`의 절대 하지 말 것 목록과 동일)
- 테스트 파일을 대량으로 수정/삭제하는 커밋이면, 커밋 전에 사람에게 승인을 받는다
  (`/approval-check` 스킬)

## 2. 커밋 단위

한 커밋 = 한 논리적 변경 (`.claude/CLAUDE.md` 코드 규칙과 동일).
작업을 여러 단계로 나눠 진행했다면, 단계마다 커밋한다. 한 번에 몰아서 큰 커밋 하나로 만들지 않는다.

**커밋 메시지 형식**

커밋 메시지는 영어로, 아래 타입 prefix를 붙여 작성한다.
**전체 메시지(제목+본문 합쳐서)는 100자 이내**로 쓴다. 넘으면 본문부터 줄이거나 생략한다.

```
{type}: {what}
```

**Type 목록**

| Type | 사용 시점 |
| --- | --- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 |
| `style` | 코드 스타일 변경 (포매팅, 세미콜론 누락 등) — 기능 수정 없음 |
| `design` | 사용자 UI 디자인 변경 (CSS 등) |
| `test` | 테스트 코드, 리팩토링 테스트 코드 추가 |
| `refactor` | 코드 리팩토링 |
| `build` | 빌드 파일 수정 |
| `ci` | CI 설정 파일 수정 |
| `perf` | 성능 개선 |
| `chore` | 빌드 업무 수정, 패키지 매니저 수정 (`.gitignore` 수정 등) |
| `rename` | 파일 혹은 폴더명을 수정만 한 경우 |
| `remove` | 파일을 삭제만 한 경우 |

예: `feat: implement soft delete for tasks (D-001)`

design decision(D-001처럼)을 따른 변경이면, 여유가 있을 때 괄호로 근거 문서를 짧게 언급한다.
100자 안에 안 들어가면 생략해도 된다 — 분량 제한이 우선이다.

## 3. 푸시 — 사람 확인 게이트

브랜치는 `main` 하나만 쓴다. 별도 브랜치를 만들지 않는다.

커밋 후 곧바로 푸시하지 않는다. 아래를 사람에게 보여주고 확인을 받는다.

- 이번에 푸시할 커밋 목록 (해시 + 커밋 메시지 전체)

**"커밋 메시지가 맞는지" 확인**이 이 게이트의 핵심이다. 커밋 메시지가 실제 변경 내용과
일치하는지, 이유가 정확히 적혔는지를 사람이 검토한다. 사람이 "푸시해" 또는 그에 준하는
명확한 승인을 준 뒤에만 `git push` 한다 (일반 푸시만, `--force`는 이 스킬의 범위 밖).

사람이 커밋 메시지를 고치라고 하면, `git commit --amend`로 메시지만 수정하고
다시 확인을 요청한다.

## 4. 완료 보고

푸시가 끝나면 아래를 보고한다.

- 커밋 목록 (해시 + 메시지)
- 푸시된 브랜치

## 하지 않는 것

- `git push --force` (승인 대상, 이 스킬 밖)
- **사람 확인 없이 푸시** — 커밋 메시지 확인 없이 곧바로 푸시하지 않는다
- 새 브랜치 생성 (`main`만 사용)
- 커밋 히스토리 재작성 (`rebase -i` 등 — 메시지 수정 목적의 `commit --amend`는 3번 흐름 안에서만 예외)
- `.env`, `secrets/` 커밋
